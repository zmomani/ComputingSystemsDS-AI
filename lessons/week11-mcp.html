Introduction

The Model Context Protocol is changing how AI assistants connect to data sources and tools. Think of it as a USB-C for AI: just as USB-C gives devices one standard way to connect, MCP gives AI systems one standard way to connect to data — a universal connector that standardizes integration.

Why MCP matters

  • Standardizes how AI models connect to data sources.
  • Reduces fragmentation in AI tool integrations.
  • Lets AI access data securely within existing infrastructure.
  • Simplifies building AI applications with added capabilities.
  • Gives flexibility to switch between LLM providers.

What is MCP?

MCP is an open standard introduced by Anthropic in November 2024 for connecting AI applications with external tools, data sources, and systems. Messages are JSON-RPC 2.0, carried over stdio (the client launches the server as a subprocess) or Streamable HTTP (the earlier HTTP+SSE transport is legacy). It addresses a core problem: AI models are isolated from data trapped in silos and legacy systems, and every new integration needs custom work.

Key characteristics - Secure — access stays within your own security boundaries. - Open — a community-driven, open-source standard anyone can contribute to. - Interoperable — works across different LLM providers. - Extensible — adapts to many kinds of data sources.

MCP Architecture

MCP uses a client–server design with three components.

Component Role
MCP Host Applications such as Claude Desktop, IDEs, or other AI-powered tools that want data through MCP. The host is where the user interacts.
MCP Client Maintains a 1:1 connection with each server and manages the protocol communication between host and server.
MCP Server Lightweight programs that each expose specific capabilities — tools (functions the model can call), resources (data the host can read) and prompts (reusable templates) — and connect to the actual data sources and tools.

Data sources - Local data sources — files, databases, and services on your computer. MCP servers can access them without sending the data to external services. - Remote services — external systems reached over the internet through APIs, e.g. GitHub, Slack, weather services.

The design is modular, and sensitive data stays within your security boundaries.

How MCP Works

  1. User query — the user asks an AI assistant a question through an MCP host such as Claude Desktop.
  2. AI determines context needs — the model recognizes it needs more information and identifies which servers may have it.
  3. Host queries servers — the host sends requests to the appropriate servers through the MCP client.
  4. Server processes request — each server accesses its data source, processes the request, and returns the relevant information.
  5. Response aggregation — the client collects and formats the responses from all servers and passes them to the model.
  6. AI response generation — the model uses the added context to produce a more informed, accurate answer.

Key protocol features - Server discovery — hosts can find which servers are available and what they can do. - Standardized schema — all exchanged data follows a consistent format models can parse. - Request/response pattern — requests use structured parameters and return structured values. - Access controls — built-in authentication and authorization protect data sources.

from mcp.server import MCPServer   # mcp 1.x: from mcp.server.fastmcp import FastMCP as MCPServer

# Create a simple MCP server
mcp = MCPServer("FileReader", instructions="Reads files from the local filesystem")

# Define and implement a tool (the JSON schema is derived from the type hints)
@mcp.tool()
def read_file(path: str) -> str:
    """Reads content from a file."""
    try:
        with open(path, "r") as f:
            return f.read()
    except Exception as e:
        return f"error: {e}"

# Start the server (stdio transport by default)
if __name__ == "__main__":
    mcp.run()

Benefits of MCP

For developers - Simplified integration — one protocol works with multiple AI models. - Modularity — components can be built and maintained independently. - Interoperability — switch between LLM providers. - Reusable components — existing MCP servers can be reused. - Built-in security patterns — security practices are part of the design.

For organizations - Data security — sensitive data stays within your security boundaries. - Productivity — AI tools can reach internal systems. - Control — governance over data access is maintained. - Future-proofing — adopt new AI models without rewiring integrations. - Cost efficiency — lower integration-maintenance costs.

For end users - Smarter responses — the AI fetches the information it needs, making answers more accurate and relevant. - Enhanced privacy — sensitive data can stay on local devices while remaining available to the assistant. - More capabilities — the AI handles more complex tasks by retrieving the right information at the right time.

Long-term vision - A universal layer connecting AI models to many kinds of data sources. - Marketplaces of specialized MCP servers for different use cases. - Advanced AI workflows that span multiple systems. - Context-awareness that carries across different applications.

What an MCP server does with JSON-RPC messages (pure Python)
import json

TOOLS = {"add": {"description": "Add two numbers",
                 "inputSchema": {"type": "object", "properties": {"a": {"type": "number"}, "b": {"type": "number"}}, "required": ["a", "b"]}}}

def handle(message):
    req = json.loads(message)
    if req["method"] == "initialize":
        result = {"protocolVersion": "2025-06-18", "capabilities": {"tools": {}}, "serverInfo": {"name": "demo", "version": "1.0"}}
    elif req["method"] == "tools/list":
        result = {"tools": [{"name": n, **spec} for n, spec in TOOLS.items()]}
    elif req["method"] == "tools/call":
        args = req["params"]["arguments"]
        result = {"content": [{"type": "text", "text": str(args["a"] + args["b"])}], "isError": False}
    else:
        return json.dumps({"jsonrpc": "2.0", "id": req["id"], "error": {"code": -32601, "message": "Method not found"}})
    return json.dumps({"jsonrpc": "2.0", "id": req["id"], "result": result})

for i, (method, params) in enumerate([("initialize", {}), ("tools/list", {}),
                                       ("tools/call", {"name": "add", "arguments": {"a": 2, "b": 40}}), ("ping/nope", {})], 1):
    msg = json.dumps({"jsonrpc": "2.0", "id": i, "method": method, "params": params})
    print("->", msg)
    print("<-", handle(msg), "\n")

# 2. An MCP client that launches the server above, lists tools, and calls one
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    params = StdioServerParameters(command="python", args=["server.py"])
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()                 # handshake + capability negotiation
            tools = await session.list_tools()         # discovery
            print([t.name for t in tools.tools])
            result = await session.call_tool("read_file", {"path": "server.py"})
            print(result.content[0].text[:80])

asyncio.run(main())
